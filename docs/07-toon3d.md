# 07 Toon3D（Phase 6 / 参照研究の適用）

調査日: 2026-10-20 / ブランチ: `claude/T7-research`
対象: [Toon3D](https://github.com/ethanweber/toon3d)（公式コードは `~/ext/toon3d` に取得して**読んだだけ**。実行はしていない）。課金APIは使っていない。

## 1. 結論

- **今回のプロジェクトの課題には直接は効かないと判断し、実行は見送った（コードと手順の調査まで）。**
- Toon3D は「アニメ・漫画のように**幾何的に整合しない数枚の絵**から、3Dシーンを再構成する」研究。入力は絵（コマ割りのスチル）で、このプロジェクトが持っている入力（Tripo のメッシュ、World Labs の背景3DGS、Blender で自由に描ける多視点画像）とは別物。
- このプロジェクトのキャラ・背景はすでに**幾何的に整合した3D**として手に入っている。Toon3D が解いている「整合しない絵を無理やり合わせる」問題が、そもそも発生していない。
- ただし、**今後「アニメの背景美術（1枚絵）やコンセプトアートから舞台を起こす」流れを足すなら**、有力な参考になる（5章）。

## 2. 何をする手法か（コードから読み取った内容）

パイプラインは4段で、実装は `toon3d/scripts/run.py`（SfM）と `toon3d/toon3d_model.py`（nerfstudio の splatfacto を継承した3DGS）。

1. **前処理**（`tnd-process-data`）: 各画像の単眼深度（Marigold）と SAM のマスクを作る。
2. **手作業のラベル付け**: ブラウザのツール（labeler.toon3d.studio）で、画像間の**対応点（キーポイント）**を人が打つ。
3. **独自のSfM**（`tnd-run`）: 深度はそのままだと画像ごとに矛盾するので、**画像ごとのカメラ（焦点距離を含む）と、深度に掛ける平行移動・スケール**を最適化して、対応点が3D上で一致するようにする。そのあと、**ARAP（as-rigid-as-possible）のメッシュワープ**で、絵の各画素に局所的な変形を許して、残った矛盾を吸収する（`warp/warp_mesh.py`、`warp/arap_utils.py`）。
4. **3DGS学習**（`ns-train toon3d`）: 上で得た密な点群で初期化し、nerfstudio の splatfacto で学習。

要点は「**絵ごとに歪みを許した形で、1つの3Dに折りたたむ**」こと。

## 3. このプロジェクトの課題との対応

| 課題 | Toon3D の効き目 | 理由 |
|---|---|---|
| 背景の黒点・針状スプラット・池の透過・光の帯 | なし | 品質の問題は3DGS表面の最適化の話。Toon3D は入力の整合性の話 |
| キャラの「切り抜き感」・のっぺり質感 | なし | キャラは Tripo のメッシュから多視点を描ける。絵の整合に困っていない |
| 背景の焼き込み照明・二重ライティング | なし | 照明の分離とは無関係 |
| 法線の不安定さ | なし | 法線を扱う手法ではない |
| 1枚絵・コンセプトアートからの舞台生成 | **あり**（要検証） | 5章 |

## 4. 実行を見送った理由

| 理由 | 内容 |
|---|---|
| 課題との接点が薄い | 上の表のとおり。GPUの学習枠（同時に1本）を使う価値が、他の手法より低い |
| 手作業が要る | 対応点のラベル付けはブラウザで人が行う。自動化されていない（ユーザーの手を借りるか、自前の自動マッチングが要る） |
| 環境が重い | nerfstudio と、`transformers==4.35.2` などの古い固定、Marigold・SAM のモデル取得（追加ダウンロード）が要る。RTX 5060 Ti（sm_120、torch 2.8）では、nerfstudio の `gsplat` のビルドで、MILo・GaussianShader と同種のつまずきが予想される |
| 公式データも大半が手元にない | 付属の3枚（`toon3d/assets/randm_*.jpeg`）は処理前の画像で、ラベルがない。公式データセットは Hugging Face からの取得が必要 |

必要になったら、`toon3d` を WSL の新しい venv に入れ、公式データセットのうち1シーンを取得して `tnd-run` → `ns-train toon3d` を動かす（半日程度の見込み）。

## 5. 持ち帰る考え方（自前実装の候補）

「アニメ背景美術を3DGSの舞台にする」流れ（World Labs のような単一画像→3D の代替・補強）を作るときの要素として:

1. **単眼深度の画像ごとの平行移動・スケールを、画像間の対応点で合わせる**。背景美術は複数カットが同じ場所を別アングルで描くことが多く、カットごとに深度のスケールがずれる。対応点で合わせる最小の最適化は、Torch で数十行で書ける（SAM もラベルツールも不要）。
2. **整合しない部分は ARAP 風のメッシュワープで吸収する**。絵は遠近法が厳密ではないので、ここで「絵の個性」を壊さず3Dに入れられる。
3. **深度で初期化した点群から3DGSを学習する**。今回の MILo/素の3DGS の学習の初期化に、点群を差し替えるだけで使える。

World Labs の背景は、すでに3DGSとして出ているので、今のところこの流れは必要ない。

## 6. 次の判断材料

- ユーザー側に「背景美術の1枚絵/複数カットを舞台にしたい」要望があれば、この手法の価値が上がる。その場合は、手作業のラベル付けなしで、自動マッチング（例: 特徴点＋深度）に置き換える自前実装から着手するのがよい。
