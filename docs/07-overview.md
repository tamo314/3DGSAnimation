## 1. 一言でいうと

**公式コードをそのまま使って表現が良くなったものはなかった。** ただし、課題の原因が「どこにあるか」が分かり、**自前で実装する価値のある考え方が3つ**に絞れた。

| 優先 | 持ち帰る考え方 | 元の技法 | 狙い |
|---|---|---|---|
| 1 | **Tripo メッシュにガウシアンを直接結びつける**（三角形ごとにガウシアンを置き、メッシュ変形に追従） | Frosting | アニメーション（ボーンでメッシュを動かす）＋表面の微細な質感。針状スプラット・外れ値が出にくい |
| 2 | **法線の整合を正則化として足す**（近傍の面の向きをそろえる） | MILo | 法線が安定し、接地影・再ライトが使える。背景の針状スプラットにも効く見込み |
| 3 | **属性を分けて持たせる**（拡散・鏡面・粗さ・法線）。キャラだけに適用 | GaussianShader | 再ライト。背景の焼き込み照明とは別に、キャラ側の光を合わせる |

## 4. 原因の整理（どこに課題があるか）

1. **背景の欠点（黒点・針状スプラット・池の透過）は、技法の問題ではなく入力の問題**。背景には元の多視点写真がなく、World Labs が出した3DGSを描画し直して学習する（自己蒸留）しかないため、MILo のような再学習は欠点をそのまま引き継ぐ。直すなら、(a) 外れ値の剪定（自前）、(b) 欠点の少ない生成（World Labs の再生成。有料のため要相談）。
2. **キャラの「切り抜き感」は、メッシュ描画から3DGS描画に変えるだけで弱まる**（輪郭が背景と混ざる）。MILo の寄与は法線の質と軽さで、見た目の差は小さい。のっぺり質感は、質感の細かさ（テクスチャ解像度・法線・粗さ）の問題で、Blender 側（PBR素材）か、メッシュ連動の層で足すのが筋。
3. **背景の焼き込み照明は、どの技法でも分離できない**（法線の質が上がっても R² は 0.17 まで）。T5 の方針（背景は焼き込み固定、キャラの光を背景に合わせる）を変える理由は見つからなかった。
4. **絵柄の置き換え（G-Style）は、このプロジェクトの目的（形と色は保ち、微細な質感・光だけ足す）と逆向き**。強さの調整もできない。

## 5. 推奨の進め方

1. **（最優先）メッシュ連動のガウシアン層を自前で作る**（[07-frosting.md](07-frosting.md) 7章）。Tripo メッシュの三角形にガウシアンを置き、既存の多視点画像で色・不透明度・オフセットだけ最適化する。まずは静止ポーズで、素の3DGS（24万個）と同等以上の見た目が出るかを確認し、その後、ボーンで腕を動かして追従を確認する。アニメーション実証（このプロジェクトの将来目標）に直結する。
2. 背景の外れ値の剪定を自前で書く（不透明度・色・スケールの外れ値）。元の背景PLYを直接直す。
3. 法線整合の正則化を、上の自前の学習ループに足す。
4. 照明を一様にしたデータで、GaussianShader 流の属性分離（キャラのみ）を自前で試す。
5. ゲームの実行環境（Unity、aras-p/UnityGaussianSplatting）には、素の3DGS形式（PLY）が必要なので、層の出力は標準形式にそろえる。

## 6. 公式コードをプロジェクトに取り込まない理由

- ライセンス（Inria/MPII系の非商用研究ライセンス）。このプロジェクトの Development Rules（既存の研究コードは参考にとどめ、独自実装する）とも合わない。
- 新しい GPU（sm_120）・新しい torch への追従が必要で、ビルド・実行の回避策が多数要った（各記録に残した）。パイプラインの土台にするには脆い。
- 速度（GaussianShader 約13倍遅い、MILo 約7倍遅い）が実験の回転を落とす。

## 7. 再現（環境）

WSL2 Ubuntu に micromamba（`t7`）と venv（`gshader`、`gstyle`、`frosting`）。`scripts/wsl/env_t7.sh` を source して使う。主なつまずき（ビルド・ABI・EGL・torch.load）は各記録の「つまずき」の章と、`scripts/wsl/` のコメントにまとめた。大きな生成物（PLY・メッシュ）は Git に入れず、`experiments/T7/` に置いている。
