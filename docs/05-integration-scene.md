# 05 統合シーンの構築（T4 / Phase 3）

実施日: 2026-10-20 / ブランチ: `claude/T4-integration`（T3・T1・T2 をマージ）/ 環境: Blender 5.2.1 LTS、KIRI v5.1.0、RTX 5060 Ti
目的: 背景3DGS（World Labs `forest_clearing`）とキャラメッシュを同じ座標空間に置き、5視点で破綻と不整合を調べる。課金APIは使っていない。

## 1. 結論

- 背景3DGSをKIRIで取り込み、キャラ（`girl_healer.glb`）と同じ座標空間で描画できた。**5視点とも背景は破綻なく描画され、遮蔽も正しい**（[画像](img/05-integration-5views.jpg)）。
- 縮尺は**生成時のまま（1.0）**で確定済み（アーチ約23m先・高さ約10m、キャラ1.2m）。縮尺は `build_integration.py` の `WORLD_SCALE` 1か所で変えられる（0.5 と 1/3 でも描画が通ることを確認した）。
- 背景は **full_res（192万）を使うこと**。500k はKIRIの描画では木の葉に針状ノイズと黒い点が目立ち、full_res のほうが明らかに鮮明（[比較](img/05-500k-vs-fullres-crop.jpg)）。
- **キャラ位置の地面は z=0 ではなく約0.1〜0.2m高かった**。キャラを z=0 に置くと足が地面に埋まる。位置を (0.4, 0)、足元の高さを 0.13m にした。
- 不整合は主に「キャラの見た目が背景から浮く」（暗く平板、接地影なし）。次のライティング調整の課題。

## 2. 統合シーンの仕様

座標: キャラ位置付近を原点とするBlender世界座標（X右・Y前方=アーチ方向・Z上、m）。元カメラは (0, −3.5, 0.975)。

| 要素 | 置き方 |
|---|---|
| 背景 | `forest_clearing_full_res.ply`（RDF）を X軸 −90° 回転、スケール = `metric_scale_factor`(1.6804) × `WORLD_SCALE`、位置 = 元カメラ位置 (0, −3.5, 0.975)×`WORLD_SCALE`。KIRIのプロキシ（Empty）に変換、元メッシュは非表示 |
| キャラ | `girl_healer.glb`（前方 −Y、足元原点、身長1.2m）。位置 (0.4, 0)、足元高さ 0.13m。向きは −Y（5視点のカメラ側）のまま |
| 石造アーチ | 背景に含まれる。キャラの約20m後方（+Y側）、高さ約10m、小道の奥 |
| 太陽（仮） | PR #1 の光源推定: 方位17.6°・仰角24.2°（Blender回転 65.8°, 0°, 162.4°）、色 5050K（1.0/0.834/0.621）、角径6°、強さ3.0。ワールド光は強さ0.10（太陽:環境光 ≒ 4）。**KIRIのライト反応は切って**、背景は焼き込み色のまま描く |
| カメラ | `scripts/background/camera_paths_background.json` をそのまま使用（`create_cameras_from_json()`）。1440×1080、世界固定 |

カメラはキャラが動いても世界固定のまま（背景の自由空間に合わせて詰めた位置のため）。

再現:

```powershell
powershell -ExecutionPolicy Bypass -File scripts/blender/run_integration.ps1 -Out experiments/T4/headless
```

`.blend` と5視点PNGが出る（Git管理外）。実行は決定的で、GUI（Blender MCP）での描画とピクセル一致を確認した。
GUI（Blender MCP、ポート9880）では `import build_integration as bi; bi.build(); bi.render_all(out)` を `execute_code` で呼ぶ。
`.mcp.json` のポートは 9880（T4用）。他スレッドのBlender（9876 / 9877 など）には触れていない。
所要: 取り込み約25秒（full_res）、1視点の描画約3〜5秒。

## 3. キャラ位置の測定（`scripts/blender/analyze_ground.py`）

背景PLYを世界座標に変換し、キャラ位置周辺のスプラットを数値で調べた。

- キャラ位置 (0, 0) の地面は **z ≈ 0.17m**（半径25cm、不透明スプラットの中央値。5〜95%で 0.14〜0.22）。元カメラ直下の地面が z=0（視点高0.975m）なので、小道は奥のアーチへ向かって緩く上がっている（y=−1 で約0.05、y=0 で約0.17、y=+1 で約0.22）。
- 小道は x 方向に傾く。x=0.5 で 0.11、x=1.0 で 0.07 まで下がる。
- 砂色（小道）の割合は x≈0.25〜1.0 で高く（y=−1 では x=0〜1.25 が約70〜90%）、苔や草の左右 x<−0.5・x>1.25 と区別できる。**小道の中央は x≈0.4〜0.6** なので、キャラは (0.4, 0) に置いた。
- 注意: 暫定位置 (0, 0) は小道の左寄りだった。

## 4. 背景の破綻調査（5視点）

| 視点 | 結果 |
|---|---|
| front_wide | 良好。古木・アーチ・滝・池・小道がそのまま立つ。黒い小さな点が葉の間に少し残る（full_res では少数） |
| character_medium | 良好。地面・池・根が連続。キャラの足元は砂地と苔の境 |
| dappled_low | 光芒・樹冠・青空が高精細。樹冠の左上に光の帯のにじみ（T1の確認画像にもあり、背景生成物そのものの性質） |
| side_depth | 良好。アーチの側面と奥の木々の視差が保たれる |
| high_oblique | 許容。池の水面が透過気味でぼけ、最奥の岩肌と右下の石壁に引き伸ばしが出る（T1の所見と同じ） |

- 真下からの視点（地面を真上から見る）は崩れる（未観測の角度で針状に伸びる）。KIRIは平行投影非対応で、正射影カメラは使えない。
- 500k と full_res の差: 500k は葉に針状の細長い斑点と黒い点が多く、全体に甘い。full_res は T1 のSpark描画に近い鮮明さ。この世界では full_res が正解。

## 5. キャラと背景の不整合

1. **ライティングが合っていない**: 太陽が右上奥の逆光で、キャラの正面は日陰になる計算。環境光が弱い（0.10）ため、キャラは暗く平板で、明るい背景から「切り抜き」に見える（特に dappled_low の青空の前）。次の段階で、環境光の色と強さ、縁取り光（リムライト）を調整する。
2. **接地影がない**: 背景に落ちるキャラの影も、背景の木の影が落ちるキャラもない。足元が浮いて見える所がある（character_medium の右足）。KIRIの影（メッシュ→ガウシアン、Cached Shadows）で対処する想定（T3の知見）。
3. **太陽の向きが推定とずれる可能性**: dappled_low の背景に写った太陽の中心から世界座標の向きを逆算すると、**仰角約38°・方位約41°（+Yから+Xへ）**。T5a の推定（仰角24°±7°、方位18°±9°）の幅を外れている。背景に焼き込まれた影の向きも測って、どちらに合わせるか決める必要がある。
4. **接地面の高さ**: 小道に傾斜があり、キャラが動くと足元の高さが合わなくなる。ゲームでは地面メッシュ（コライダー）の高さ合わせが必要（`forest_clearing_collider.glb` は疎で未検証）。
5. **キャラの画風と背景の質感差**: キャラは平坦なテクスチャ、背景は高精細なガウシアン。質感の差は意図的な研究対象で、この段階では調整していない。
6. **縮尺**: 縮尺1.0で、キャラ（1.2m）は背景に対して小さい。front_wide でキャラが画面の高さの約3割、side_depth・high_oblique ではやや遠景の人影の大きさ。アーチ（10m）との比は約1:8。見せ場として足りなければキャラ寄りのカメラが別途必要（既存5視点は世界の自由空間に合わせてあり、これ以上近づける余地は小さい）。

## 6. 試したことと失敗

- 縮尺 1/3 と 0.5 も試した（一時的な仮案）。1/3 ではカメラも縮むため、キャラが画面に大きく写りすぎて切れる（character_medium は腰から下だけ）。結局 1.0 に確定。
- 真上からの俯瞰（地面確認用）: KIRIは平行投影を正しく扱わず崩れる。透視でも未観測の角度で崩れる。位置合わせは測定スクリプトで数値化した。
- 深度PNG（`r2_depth`）は値が0〜255に潰れて高さ測定に使えなかった。測定はPLYの数値で行った。

## 7. ファイル

- `scripts/blender/build_integration.py`: シーン構築。`WORLD_SCALE` / `BG_VARIANT` / `CHAR_POS` / `CHAR_GROUND_Z` / `CHAR_YAW_DEG` などの定数を先頭に集約
- `scripts/blender/run_integration.py` / `.ps1`: ヘッドレス再現（.blend保存 + 5視点描画）
- `scripts/blender/probe_integration.py`: 検証用カメラ（真上など）
- `scripts/blender/analyze_ground.py`: 背景PLYからの地面高さ・小道中心の測定
- `scripts/blender/contact_sheet.py`: 5視点のコンタクトシート
- 画像: `docs/img/05-*.jpg`。統合シーンの `.blend`（約150MB）はGit管理外（`experiments/T4/headless/integration.blend`）
