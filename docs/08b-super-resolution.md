# 08b 超解像でどこまで精細にできるか（T8 続き）

実施日: 2026-10-21 / ブランチ: `claude/T8-hq-bake` / 前提: [08-hq-bake.md](08-hq-bake.md)（同じキャラ・同じ描画条件・同じ3DGS学習設定）
問い: 「超解像の手法でどこまで精細度を上げられるか」。08で、近寄ったときの上限は3DGSではなく**元のTripoテクスチャ（約0.5mm/texel、にじんだ絵画調）**にあると分かったため、
超解像（SR）を2か所に当てて比べた。

- **(a) テクスチャ側SR**: Tripoのベースカラー（4096²）をSRで8192²にし、Blenderで同じ視点を再描画 → 3DGSに焼き込む。
- **(b) 出力側SR**: 3DGSを2048²で描いた画像をSRで4096²にし、4096²のBlender正解と比べる（実行時に後段で足す想定）。

超解像モデルは Real-ESRGAN の anime 6B（`RealESRGAN_x4plus_anime_6B.pth`、sha256 `f872d837d3c90ed2e05227bed711af5671a6fd1c9f7d7e91c911a61f155e99da`）。
Real-ESRGAN配布の重みを spandrel で読み込み（pickleを直接実行しない。入手元URLの記録は残していないので、再入手時は公式リリースと上のsha256を照合すること）、自前のタイル処理（`scripts/character/sr_texture.py`）で×4にしてから面積平均で縮小した。研究コードの改変はしていない。

## 1. 結論

1. **テクスチャSRは「効くが控えめ」。** 同じ視点の正解画像で、強い輪郭（勾配>0.05）の画素が顔で+29%、寄り（0.35〜0.4m）で+49〜57%増え、高周波エネルギーも+20〜64%増えた。
   目の輪郭線・まつ毛・髪の筋が一段くっきりし、ベタ面のにじみが減る（[図](img/08b-sr-texture-zoomface.jpg)の3列目）。ただし平均の勾配強度は+1〜8%と小さく、**絵柄が別物になるほどは変わらない**。
   SRは元の画像に無い情報は作れず、潰れた線を「それらしく」整えるだけ（元から無い継ぎ目や線は戻らない）。
2. **3DGSは、SRテクスチャを元テクスチャと同程度の忠実度で焼き込める。** それぞれ自分の正解に対して、全身〜顔のPSNRは0.2〜0.3 dB以内の差（G 31.65 → S1 31.48 dB、顔）。
   LPIPSは全視点で改善（顔 0.109 → 0.095、上半身 0.055 → 0.046、リング 0.029 → 0.025、寄り 0.195 → 0.180）。ガウシアン数は+5%（56万 → 59万）。
   つまり、**テクスチャを良くすれば3DGSの絵もそのぶん良くなる**（[図](img/08b-sr-texture-zoomface.jpg)の4列目）。
3. **それでも0.35mまで寄ると、3DGSの鮮鋭度は正解の約0.65倍で頭打ち。** 元テクスチャ（G）0.650、SR（S1）0.648。SR後の正解が鋭くなったぶん、3DGS側は追従できていない（ガウシアンの細かさと学習視点の距離が制約）。
4. **寄り視点（0.4m）を学習に足すと、アップは少し良くなるが全体は少し悪くなる。** ズーム顔の鮮鋭度 0.650 → 0.675、輪郭帯PSNR 19.3 → 20.7 dB。一方リング・上半身・顔のPSNRは0.7〜0.9 dB低下（ガウシアンが寄りに回り、全体に薄くなる）。
   同じガウシアン予算なら、距離ごとの割り振りの設計が要る。
5. **出力側SRは、鮮鋭度は上がるが正解への近さは上がらない。** 2048²描画を×2したとき、輪郭の鮮鋭度比はbicubic 0.59 → SR 0.75、高周波比は0.19 → 0.93と**見た目はくっきり**するが、PSNR 30.27 → 29.57 dB、LPIPS 0.195 → 0.203と**正解からは少し遠ざかる**（線が正解と違う位置・形で描き直されるため。[図](img/08b-output-sr-zoomface.jpg)の2列目）。
   3DGSを4096²で直接描いても鮮鋭度は0.59のまま（学習した細かさ以上は出ない）なので、**「寄って見せる」だけなら出力SRで見た目は補える**が、絵柄が整形される副作用がある。

**判断**: 最初の一手はテクスチャ側SR（安価で3DGSに素直に乗る）。ただしそれだけでは「アニメの線が一切粗くない」には届かない。線・目はSR前提でなく、手描き/再ペイントか専用の高解像テクスチャが必要。詳細は6章。

## 2. 実験の設計

| 名 | テクスチャ | 学習視点 | 正解（評価の物差し） | ガウシアン数 | PLY |
|---|---|---|---|---|---|
| G | 元（4096²） | 全身・上半身・顔（08のG） | 元テクスチャのBlender描画 | 563,673 | 134 MB |
| G2 | 元 | G + 寄り(0.4m) 40視点 | 同上 | 540,616 | 129 MB |
| S1 | SR（8192²） | G と同じ | SRテクスチャのBlender描画 | 591,737 | 141 MB |
| S2 | SR | G2 と同じ | 同上 | 562,734 | 134 MB |

- 全構成: SH3、30000反復、既定の密度化、2048²、公式3DGS系の学習コード（無改変）。評価視点は未学習（k%8==0）。
- **注意: G/G2とS1/S2は別の正解で採点している**（SRテクスチャの絵が正解）。「同じ物差し」での比較ではなく、「それぞれの目標をどれだけ写せたか」と「目標自体の細部がどれだけ増えたか」を分けて見る。
- 寄り視点（close）は 0.4m・40視点（評価10視点）。ズーム顔は 0.35m（08と同じ）。
- 出力側SR: モデルG、顔(0.7m)・ズーム顔・寄りの評価29視点。正解は同じ視点を4096²で描いたもの。

## 3. 結果

### 3.1 テクスチャSRで正解の細部はどれだけ増えたか（同じ視点、SR/元の比）

| 種類 | 勾配強度 | 高周波エネルギー | 強輪郭の画素割合 |
|---|---|---|---|
| リング(全身) | 1.01 | 1.20 | 1.05 |
| 上半身 | 1.03 | 1.38 | 1.16 |
| 顔(0.7m) | 1.04 | 1.32 | 1.29 |
| 下半身 | 1.05 | 1.64 | 1.40 |
| ズーム顔(0.35m) | 1.08 | 1.23 | 1.55 |
| ズーム上半身 | 1.06 | 1.46 | 1.57 |
| 寄り(0.4m) | 1.08 | 1.24 | 1.49 |

近づくほど（テクスチャが引き伸ばされるほど）SRの効果が大きい。全身では差がほぼ出ない。

### 3.2 3DGSの評価（各自の正解に対して。PSNR=ROI、輪郭=輪郭帯PSNR、鮮鋭=輪郭の鮮鋭度比）

| 種類 | 指標 | G | G2 | S1 | S2 |
|---|---|---|---|---|---|
| リング | PSNR / LPIPS | 32.41 / 0.029 | 31.65 / 0.032 | 32.14 / 0.025 | 31.38 / 0.028 |
| 上半身 | PSNR / LPIPS | 33.51 / 0.055 | 32.71 / 0.059 | 33.33 / 0.046 | 32.56 / 0.050 |
| 顔(0.7m) | PSNR / LPIPS | 31.65 / 0.109 | 30.98 / 0.110 | 31.48 / 0.095 | 30.85 / 0.096 |
| ズーム顔(0.35m) | PSNR / LPIPS | 27.85 / 0.299 | 28.69 / 0.293 | 27.55 / 0.284 | 28.37 / 0.279 |
| ズーム顔 | 輪郭PSNR / 鮮鋭 | 19.28 / 0.650 | 20.67 / 0.675 | 19.81 / 0.648 | 21.02 / 0.675 |
| 寄り(0.4m) | PSNR / LPIPS | 35.70 / 0.195 | 34.52 / 0.199 | 35.43 / 0.180 | 34.30 / 0.185 |
| 寄り | 輪郭PSNR / 鮮鋭 | 23.63 / 0.852 | 23.39 / 0.847 | 24.63 / 0.849 | 24.31 / 0.846 |

（ズーム上半身、下半身、ベタ面PSNR・ノイズ比などの全数値は [08b-sr-metrics.json](08b-sr-metrics.json)。ベタ面のノイズ比はどれも0.03〜0.2で、ざらつきは出ていない。）

読み取り:
- SRテクスチャ化（G→S1）でPSNRは−0.1〜−0.3 dBとほぼ同じ、LPIPSは全種類で改善。SRで増えた細部（輪郭）を写せている。輪郭帯PSNRはS1が上回る（顔 24.16 → 24.68、寄り 23.63 → 24.63）。
- 寄り視点を足したG2/S2は、ズーム顔の輪郭が改善する一方、他は軒並み低下。PSNRの低下はアップの高周波に容量が回ったことと、学習視点が増えて同じ反復数で薄くなったことが原因と見ているが、切り分けは未実施。
- 鮮鋭度比はどの構成でもズーム顔で0.65〜0.68。08で示した「学習距離の外挿は効かない」はSRテクスチャでも変わらない。

### 3.3 出力側SR（モデルG、4096²正解、29視点）

| 方法 | PSNR | LPIPS | 輪郭の鮮鋭度比 | 高周波比 |
|---|---|---|---|---|
| bicubic ×2（2048描画） | 30.27 | 0.195 | 0.59 | 0.19 |
| SR ×2（2048描画） | 29.57 | 0.203 | 0.75 | 0.93 |
| 3DGSを4096²で直接描画 | 30.02 | 0.202 | 0.59 | 0.11 |

SRは高周波を「足す」ので指標上は鮮鋭に見えるが、足した細部は正解の位置と合っておらず、PSNRとLPIPSは悪化する。画像は[こちら](img/08b-output-sr-zoomface.jpg)。
絵画調の滲みが「整った塗り」に変わるため、見た目の好みとしては良い方向になる場合もある（ただし線のゆらぎや塗りの質感が整形され、キャラごとの味が変わるリスクがある）。

## 5. 失敗・つまずき・注意
- 出力側SRの指標計算がGPUメモリ不足で2回落ちた（学習S2と同居）。LPIPSを1024pxタイルで平均する形に変えて解決（`compare_sr.py`）。
- G/G2とS1/S2は正解が違うので、数値の直接比較は厳密にはできない（2章）。「SRの正解自体が鮮明になった」ことは3.1で別に測った。
- S2の学習は他ジョブと同居で6740秒（S1は3669秒）。時間は参考値。
- SRモデルは1種類（Real-ESRGAN anime 6B）だけ。他モデル（より大きいモデルや拡散ベースのSR）は未試験。
- 評価はこれまで通り静止・黒背景・補間視点。

## 6. 次の一手（判断材料）
1. **テクスチャSRは採用して良い**（安価・再現可能・3DGSに素直に乗る）。ただし「線が一切粗くない」ためには、目・眉・輪郭線は別途**手描き/再ペイントした高解像テクスチャ**にする。SRは最後の下地作りの位置づけ。
2. **近距離の鮮鋭度（0.65倍の壁）は、ガウシアンの細かさと学習視点の問題。** 候補: 顔だけ別チャンクで密度を上げる（密度化しきい値を下げる/分割を増やす）、学習視点を距離ごとに重み付けする、SH0＋細かいガウシアンにするなど。次スパイクで顔専用の学習を試す価値がある。
3. **出力側SRは「寄ったときの見た目の補助」として使うかを、見た目の好みで決める。** 指標上は正解から遠ざかるので、忠実度を取るなら使わない。使う場合も、実行時の負荷（GPU推論）と時間方向のちらつき（アニメ時）を別途確認が必要。
4. 寄り視点を足すと全体が下がる件は、ガウシアン予算を増やした構成（E相当）で再確認する。

## 7. 再現手順
1. テクスチャ抽出: `python scripts/character/extract_glb_textures.py`（GLBからベースカラー等）。
2. SR環境: `scripts/wsl/setup_sr_env.sh`（uvで venv 作成、torch+spandrel）。重みは Real-ESRGAN 公式配布を `~/work/t8/sr/weights/` に置く（sha256は冒頭）。
3. テクスチャSR: `~/venvs/sr/bin/python scripts/character/sr_texture.py --src basecolor_1.jpg --weights ... --out basecolor_sr_anime6b_8k.png --final 8192 --fp16`。
4. 再描画: `scripts/blender/run_hq_master_sr.ps1`、寄り視点は `run_hq_close.ps1`（`render_hq_master.py --preset close --basecolor ...`）、4096正解は `run_hq_4k_gt.sh`。
5. データセット: `scripts/gaussian/make_hq_dataset.py`（`--master` カンマ区切りで結合）、学習・評価は `scripts/wsl/queue_t8d.sh`（S1, G2, S2）。
6. 細部の増加: `scripts/gaussian/gt_detail.py <元master> <SR master>`。出力側SR: `scripts/wsl/osr_pipeline.sh <出力名> <SH> <タグ>` と `cmp_osr.sh`。図: `t8_crops_sr.py`、`t8_crops_osr.py`。
7. Git管理外: `experiments/T8/`（画像・データ）、WSL上の学習結果とSR重み。
