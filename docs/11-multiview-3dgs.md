# 11 元画像から多視点画像を生成して3DGSにする検証(T11)

実施日: 2026-10-21〜22 / ブランチ: `claude/T11-multiview-3dgs` / 環境: RTX 5060 Ti 16GB、WSL2(gsplat 1.5.3, torch 2.8)、Codex CLI 0.163.0
目的: Tripoの3Dモデルを土台にする限界を避け、**元のAI生成キャラ画像から高精細な多視点画像を作り、3DGSを学習する方法**が、顔のアップでどこまで精細に出るかを確かめる。paint3(T10のBlenderルック)と顔アップを並べて比べる。

## 0. 第2ラウンド(連鎖生成)の要点 — こちらが最新の結論
隣の視点の顔アップを参考に渡して10°刻みで順に生成し(連鎖生成、正面から左右へ±180°の37枚)、同じ手順で3DGSを学習した。

| 項目 | 結果 |
|---|---|
| 連鎖生成した画像 | 正面〜±120°では顔・髪・飾り・刺繍の細部が隣と揃い、枠・倍率・光もほぼ保たれた([図](img/11-chain-faces.jpg))。背面側(±130°以降)は髪型・色が少しずつずれ、+180°と-180°の継ぎ目で食い違う(正面から+側は三つ編みが続くが、-側は三つ編みのない髪になる)。背面は参考程度。 |
| 3DGSの中間視点 | 独立生成(c4)で出ていた「髪の筋が顔の前に浮く・顔がまだらになる」が消え、10°の間の視点(15°/25°/35°…)でも顔・三つ編み・飾りが一貫([図](img/11-chain-novel-views.jpg))。 |
| ぼけ | **姿勢補正を切った連鎖(c9_nopose)が最も鮮明で一貫**。髪の筋、目の虹彩、リボンの縁、マントの刺繍がくっきり([図](img/11-chain-zoom.jpg)、zoom6の拡大)。姿勢補正あり(c8_nominal)はやや柔らかい。 |
| 位置合わせ | 連鎖生成は枠が揃っているので、**名目の方位のまま、全視点で共通の倍率・注視点**にするのが最良。画像から視点ごとに方位を推定し直す(c8_aligned)と、推定が±10〜25°ぶれて(+50°→43°、+60°→68°など)かえって崩れる。連鎖生成の方位は元々ほぼ名目どおり。 |
| 現時点の判定 | **「連鎖生成した多視点を、名目方位のまま3DGSにする」方式は、顔アップで一貫性とくっきり感を両立できる。** 独立生成より明らかに良い。密度を上げた版(c10)は髪がわずかにくっきりするが肌にざらつきが出るので、c9_nopose(79万点)を推奨。 |

## 1. 結論(第1ラウンド: 独立生成)

| 項目 | 結果 |
|---|---|
| 生成した多視点画像そのもの | **非常に良い。** 元画像5枚を参考に渡すと、衣装・髪・小物が揃った画像が方位ごとに出る。顔アップはまつ毛・髪の筋・虹彩が元画像よりはるかに細かく、paint3の顔(粘土っぽい)より明らかに上。 |
| 3DGSにした結果(学習した視点) | 顔の形・目・髪の流れは元の生成画像どおりに出るが、**生成画像より一段ぼける**(30万点)。ガウシアンを420万点まで増やすと目はくっきりする。 |
| 3DGSにした結果(学習していない視点) | **15°刻みの顔アップ18枚でも、視点の間が安定しない。** ±10〜20°は概ね成立するが、30°付近や-40°付近で、髪の筋が顔の前に浮く・顔がまだらになる破綻が出る。ガウシアンを増やすほど学習視点は鮮明になるが、間の視点は逆に悪化する。 |
| 原因の見立て | 視点ごとに独立に生成した画像は、細部(髪の筋の配置・小物の形・目の形)が少しずつ食い違い、方位も名目値からずれている(指定+30°が実際は約16°など)。3DGSは食い違いを3Dで整合させられず、**視点ごとの絵を丸暗記**する(SHを切っても同じ)。 |
| 描き直し往復(a) | 3DGSの描画をCodexで描き直すと見た目は鮮明になるが(構図は少しずれる)、それで再学習しても3DGSの結果はほとんど変わらなかった。ぼけの原因は入力の鮮明さではなく、視点間の食い違いと3DGSの当てはめ。 |
| 現時点の判定 | 「独立に生成した多視点画像を、そのまま3DGSにする」方式は、**学習視点では高精細、視点の間は破綻**で、このままでは動かせる3Dキャラにならない。生成画像の品質は有望なので、視点間の整合を作る工夫(§6)が次の課題。 |

## 3. 手順(再現可能)
1. **切り抜き** `scripts/t11/matte.py`: rembg(isnet-anime)。最大連結成分だけ残す。
2. **多視点生成(Codex CLI、ChatGPTの月額プラン内で追加課金なし)**
   - 全身: `scripts/t11/gen_codex.sh <方位> <出力フォルダ>`。元画像5枚(正面・左側面・3/4×2・背面)を `-i` で渡し、方位(0=正面、+=カメラがキャラの左へ)を指定して1枚生成。方位30°刻み＋75/105/135/165°で計17枚(0/90/180°は元画像を使用)。
   - 顔アップ: `scripts/t11/gen_codex_face.sh`。同じ参考画像、頭と肩。「元画像を低解像のサムネイルと見なして細部を描き込む」指示。方位 0〜±150°を15〜30°刻みで18枚。
   - 1枚あたり約1分、6〜10並列でも動いた。出力は1122×1402(元画像と同じ)。
3. **データ作成** `scripts/t11/build_dataset.py`: 全身は「頭頂〜足裏の高さ、足元の左右中心」で正規化して同じ位置・大きさに揃える(生成画像はカメラ距離・位置がばらつくため)。カメラは中心を向く弱透視(距離8、キャラ高さ=2)。方位は名目値。
4. **顔アップの位置合わせ** `scripts/t11/align_closeups.py`: 全身だけで学習した粗い3DGSの描画に対し、顔アップ画像の方位・カメラ距離(=倍率)・注視点高さ・画面内ずれを、両方を同じ強さでぼかして比べて推定(格子探索→勾配法)。推定した倍率は約2.4〜3.2、注視点高さは約0.6(キャラ高さ2、足裏=-1)。
5. **3DGS学習(自前)** `scripts/t11/gs_train.py`(gsplatのラスタライザ使用): ビジュアルハルの初期点、視点ごとのカメラ姿勢の補正(方位・回転・平行移動)の同時最適化、アルファ損失、白背景、SH可変。実行は `scripts/t11/train_gs_job.sh <データ> <run名> [引数]`(WSL)。描画は `gs_render.py`、学習視点を補正後の姿勢で描き直すのは `gs_render_train.py`。
6. 描き直し往復 `scripts/t11/gen_codex_refine.sh`: 3DGSの描画をCodexで鮮明に描き直す。

## 5. 失敗・ハマりどころ
- **名目の方位のまま公式3DGSで学習すると、全体がもやもやに曇る。** 生成画像の方位は指定どおりに出ない(指定+30°→推定16°、+45°→51°、+60°→48°など。±10〜17°ずれ)。カメラ姿勢の同時補正(c2〜)で幾らか改善。
- **生成の向きの逆転。** 顔アップの-60°を最初に頼んだら+60°を鏡にしたような向き(同じ側)で出た。「画面上で鼻が右を向く(カメラがキャラの右側を見ている)」と画面基準の向きを明示して直った(スクリプトに反映済み)。全身の負の方位(-60/-120/-150°)は先に目視で確かめなかったが、カメラ補正後の方位ずれは±9°以内で、向きの反転は見つからなかった。
- **gsplatは内部パラメータKへの勾配を返さない。** 倍率・画面中心を学習可能にしても動かない(気づくまで倍率が格子の値のままだった)。倍率はカメラ距離(=D/倍率)で表して解決。
- **姿勢の学習率を上げると暴走する(c7)。** 姿勢が全体でずれて、描画の枠も評価も崩れた。姿勢は初期推定(位置合わせ)を良くして、学習率は小さく(1e-3)保つ。
- 公式の学習コードは新しいPillowで `np.byte` 配列の `Image.fromarray` が落ちる。コードは変えず、`sitecustomize` で包んで回避(`~/work/t11/shim`)。
- Codex CLIは、標準入力が端末につながっていると「Reading additional input from stdin...」で止まる。`< /dev/null` を付ける。画像の保存先はWindowsパスでスペース・バックスラッシュのエスケープを間違えやすいので、`pwd -W` の `C:/...` 形式を使う。
- 描き直し(往復)は、構図が数%ずれ、リボンの形や刺繍が変わる。位置合わせをやり直しても3DGSの結果は変わらなかった。
- 学習時間: 30万点・20000回で約25〜47分(2本並行時は倍)、420万点・30000回で約86分。400万点を超えるとiterあたり約5倍に遅くなる。
- **(連鎖)背面側でずれる。** +180°側は三つ編みが続くが、-側(-130°以降)は三つ編みのない巻き髪に変わり、色も赤みが強くなり背景も青みが出る。生成を重ねるほど少しずつずれる(連鎖の宿命)。今回は-120°までを学習に使い、-130°以降は捨てた。背面は元画像(girl4)や全身の生成画像に頼る。
- **(連鎖)画像から方位を推定し直すと悪化する。** `align_chain.py` で共通の倍率・注視点と視点ごとの方位ずれを推定したところ、+50°→43°、+60°→68°、-50°→-41°、-60°→-69°など不規則にずれた(粗い全身3DGSでは顔の向きの手掛かりが弱い)。名目方位を使う方が良い。
- **(連鎖)姿勢補正は連鎖データでは害になる。** 視点ごとの姿勢補正をかけると、各視点が少しずつ動いて丸暗記が戻り、ぼけた(c8_nominal)。切る(c9_nopose)と鮮明になった。
- 学習時間: c9_nopose 20000回・79万点で約50分(2本並行時)、密度増(300万点超)は約90分。

## 6. 次の手(提案)
**連鎖生成は有効だった(§0)。** 続きは:
- 連鎖生成を5°刻み・全身に広げる(全身も隣の視点を条件に連鎖生成すれば、体と服も同様に一貫するはず)。背面側のずれは、元画像の背面(girl4)をもう一端のアンカーに渡し、両側から挟んで生成して抑える。
- 連鎖生成の顔アップを、メッシュ拘束つきガウシアン(T9)の教師にする(動かすため)。
- 生成画像の色ずれ(背面側)は、視点ごとの輝度ゲインを学習側で吸収する。
- 以下は第1ラウンド時点の案(1が今回実施済み):
視点間の食い違いを減らすか、3Dの拘束を足さない限り、3DGSは視点ごとの丸暗記になる。優先順に:
1. **隣の視点を条件にして順に生成する(連鎖生成)。** 前の視点の画像を参考に渡して次の方位(5〜10°刻み)を描かせると、局所的な食い違いが小さくなる。今回のように30°離れた参考から独立に描くよりも、細部が揃うはず。顔アップだけで試せる(約30枚)。
2. **メッシュ拘束つきのガウシアン(T9)に、生成した顔アップを教師として学習する。** 幾何を表面に縛れば、顔の前に髪の筋が浮く破綻は出ない。色(テクスチャ)だけが食い違いの影響を受ける。Tripoの顔の形と生成画像の顔の形の差が課題。
3. 生成の整合性が高い手段(カメラ制御つきの動画生成など)で多視点を作る。今回は未検証。
4. 3DGS側: 視点数の少ない顔は、低SH・不透明度/スケールの正則化などで丸暗記を抑える。ただし今回の c6 のとおり、密度を上げるだけでは悪化する。
- (b) 高解像画像をメッシュに投影してテクスチャにする比較は、今回は実施していない。
